# 🏗️ Project Restructuring for Vercel Multi-Domain Deployment

## 📋 Context & Goal
ปัจจุบันโปรเจกต์นี้มีการเขียนโค้ดรวมกัน หรือมีการซ้อนโฟลเดอร์ในลักษณะที่ไม่เหมาะสมต่อการ Deploy แยกส่วน (เช่น มีหน้า Main, Admin, Cafe, HBD ปะปนกันอยู่) 

**เป้าหมาย:** ต้องการให้คุณ (Cursor) ตรวจสอบและ Refactor โครงสร้างโปรเจกต์ใหม่ทั้งหมด เพื่อเตรียมตัวนำไป Deploy บน **Vercel** แบบแยก **Root Directory** สำหรับผูก Subdomain แยกกันเด็ดขาด (เช่น `www`, `cafe`, `hbd`, `admin`) โดยใช้ Git Repository เดียว

---

## 🔍 Step 1: Audit Current Structure (ตรวจสอบโครงสร้างปัจจุบัน)
กรุณาแสกนโครงสร้างไฟล์และโฟลเดอร์ทั้งหมดในโปรเจกต์นี้ แล้วสรุปปัญหาให้ฉันฟัง:
1. ตอนนี้มีโฟลเดอร์หรือไฟล์ไหนบ้างที่ทำงานปะปนกันอยู่ (เช่น Routing ของหน้า Cafe ไปรวมอยู่ใน Main)
2. มี Component หรือ Utility ใช้งานร่วมกันที่ควรถูกแยกเป็น Shared Folder หรือไม่?
3. `package.json` ปัจจุบันมีการตั้งค่าที่เหมาะสมกับการแยก Build หรือยัง?

---

## 📐 Step 2: Propose New Architecture (เสนอโครงสร้างใหม่)
ฉันต้องการให้คุณเสนอโครงสร้างแบบ **Monorepo / Workspace-style** (หรือการแยกโฟลเดอร์ระดับ Root ที่ชัดเจน) โดยอิงตามโปรเจกต์ที่จะแยกย่อย ดังนี้:
- **Main Web** (โปรเจกต์หลักของ Mild-R) -> สำหรับโดเมนหลัก
- **Cafe Event** (งานคาเฟ่นักสืบ / จองเมนู) -> สำหรับ `cafe.` subdomain
- **HBD Upload** (ระบบอัปโหลดรูปภาพ/คำอวยพร) -> สำหรับ `hbd.` subdomain
- **Admin Panel** (ถ้าย้อนกลับไปดูแล้วมี) -> สำหรับ `admin.` subdomain
- **Shared** (ถ้ามี UI หรือ Config ที่ใช้ร่วมกัน)

*เงื่อนไข:* โครงสร้างใหม่ต้องรองรับการกำหนดค่า `Root Directory` ใน Vercel ได้อย่างอิสระ โค้ดของแต่ละโปรเจกต์ต้องไม่ก้าวก่ายกัน

---

## 🛠️ Step 3: Execute Separation (ลงมือแยกโค้ดและ Refactor)
เมื่อเราตกลงโครงสร้างใน Step 2 ได้แล้ว ให้คุณดำเนินการ:
1. **Move Files:** ย้ายไฟล์ Pages, Components, Public Assets, และ API Routes ไปยังโฟลเดอร์แอปของตัวเองให้ถูกต้อง
2. **Fix Imports:** อัปเดต Path การ Import ทั้งหมดที่พังหลังจากการย้ายไฟล์ให้กลับมาใช้งานได้ 100%
3. **Isolate Configs:** แยกไฟล์ตั้งค่า เช่น `tailwind.config.ts`, `tsconfig.json`, `next.config.js` (หรือ config ของเฟรมเวิร์กที่ใช้) ให้แต่ละโฟลเดอร์มีเป็นของตัวเอง เพื่อให้ Vercel Build แยกกันได้โดยไม่พัง
4. **Clean Up:** ลบไฟล์ซ้ำซ้อน รหัสที่ไม่ได้ใช้ (Dead Code) หรือ Route ที่ตั้งค่าผิดจากการซ้อนโฟลเดอร์แบบเก่า

---

## ✅ Step 4: Verification (ตรวจสอบความสมบูรณ์)
เมื่อ Refactor เสร็จแล้ว กรุณาตรวจสอบ:
1. ถ้าฉันเข้าไปที่โฟลเดอร์ของแต่ละโปรเจกต์ (เช่น `cd apps/cafe`) ฉันสามารถรันคำสั่งเริ่มเซิร์ฟเวอร์ (เช่น `npm run dev`) ได้อย่างอิสระใช่หรือไม่?
2. มีจุดไหนที่ยังผูกติดกันจนอาจทำให้ Vercel Build พังหรือไม่?
3. สรุปคำสั่งที่ฉันต้องตั้งค่าในช่อง **"Root Directory"** บนหน้า Dashboard ของ Vercel สำหรับแต่ละโปรเจกต์ให้ด้วย

**เริ่มต้นการทำงานได้เลย โดยเริ่มจาก Step 1!**
